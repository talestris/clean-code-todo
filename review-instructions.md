# Инструкция для AI-ревьюера проекта "Clean Code Todo"

## Цель
Провести комплексный статический анализ (код-ревью) файлов `index.html`, `style.css` и `app.js` на соответствие принципам чистого кода (Clean Code) и выявить потенциальные проблемы в унаследованном коде.

## Границы проверки
* **Что проверять:** Логику манипуляции DOM, качество именования переменных и классов, избыточность комментариев, дублирование кода, чистоту функций.
* **Чего НЕ трогать:** Не предлагать переписывать приложение на фреймворки (React/Vue/Angular), не предлагать внедрять сборщики (Webpack/Vite), не изменять общую функциональность приложения. Помощник должен только анализировать код, а не редактировать файлы.

## Критерии готовности анализа
Ревью считается завершенным, когда код проверен по следующим 5 категориям:
1. Мертвый или неиспользуемый код.
2. Дублирование обработчиков событий и бизнес-логики.
3. Имена, требующие комментариев для понимания.
4. Комментарии, дословно пересказывающие код.
5. Избыточно длинные или перегруженные функции.

## Формат вывода результатов
Результат анализа должен быть сохранен в файл `review-report.md` на русском языке. Замечания должны быть сгруппированы строго по указанным выше 5 категориям. 

Каждое замечание должно состоять из четырех обязательных частей:
1. **Место в коде:** Имя файла и конкретная строка/функция.
2. **Проблема:** Суть нарушения правил чистого кода.
3. **Условие проявления:** При каких действиях или сценариях эта проблема мешает чтению кода или вызывает баги/утечки памяти.
4. **Способ проверки:** Как разработчик может убедиться, что проблема локализована или успешно исправлена.
